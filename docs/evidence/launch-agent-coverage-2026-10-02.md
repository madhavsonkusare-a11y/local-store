# Launch-app agent access

The selected ten Windows launch apps have four compiled provider kinds. These
are useful bounded access paths, not unrestricted automation of each app.
Installation proof, provider proof and a client's current permission are three
separate facts. The other 42 approved offerings remain unverified for content.

| App | Method and supported actions | Owner setup and limits |
| --- | --- | --- |
| Memos | Typed API: read private notes; request creation of an exact private note | Connect an app token and grant one client access; every write needs separate, short-lived approval. No arbitrary note update/delete. |
| n8n | Official instance MCP: workflow summaries; request a fixed note table and read its rows | Enable instance MCP, connect its token, explicitly expose workflows for detail reads. No workflow execution, code, generic MCP proxy or credential reads. |
| PrivateBin | Isolated browser: create an approved paste and read connection-created pastes | Explicitly prepare the pinned browser; separate client grant and exact write approval. Non-burning one-day pastes only, at most 32 retained keys. No arbitrary browser sessions or historical paste links. |
| Flatnotes | App files: list and read ordinary Markdown notes | Explicit exact client/app file grant; no app token imported. Maximum 64 KiB per note; no database, hidden files, traversal, links or writes. |
| Gitea | Typed API: account-owned repository summaries, names, descriptions and private flags | Connect a scoped user token and exact read grant. No clone URLs, credentials, commits or repository mutation. |
| WordPress | Fixed XML-RPC: permitted private/draft/published post summaries and bounded text | Connect username:password and exact read grant. No writes, generic XML-RPC methods, entity resolution or following returned URLs. |
| Kanboard | Fixed JSON-RPC: current-user projects and task summaries | Connect a strong user credential or personal API token and exact read grant. Global RPC key, task changes, project tokens and arbitrary methods are refused. |
| Immich | Typed API: accessible asset identity, filename, type and dimensions | Connect a scoped API key and exact read grant. No original file paths, location metadata, uploads, downloads or deletion. |
| Jellyfin | Typed API: media identities, names and types | Connect an app-issued API/user token and exact read grant. No filesystem paths, playback links or media mutation. |
| Uptime Kuma | Authenticated metrics: monitor identity, name, type and status | Connect username:password or username:API key; anonymous metrics must return 401. No monitored addresses, private tags, target requests or configuration writes. |

All credential-based connections use Windows account protection. Connecting
grants no client access. Each installed alias has its own permission scope;
another client's grant does not authorize this client. Revocation, expiry,
credential replacement and disconnect/reconnect refuse earlier scopes.
Dedicated credential/URL fields are removed from projections. Ordinary user
text may contain URLs; it remains data and is never followed.

The production directory and installation capability display verify embedded
receipts against exact provider/test/fixture bytes and a 30-day expiry. Changed,
missing, failed or stale proof withholds the verified claim. It never implies
that an app is connected or a client currently has permission.

Run `python scripts/check-agent-provider-evidence.py` for the strict ten-app
gate. `--allow-pending` is a source-development report, not product acceptance.
CI uses the report because source publication must remain possible after a
receipt expires; the Windows product gate requires all ten current proofs.
The exact real receipts live beside this document and are generated by opt-in
serial owned-engine tests. An image pull, parser test or mocked UI is not proof.

Kanboard's first refused attempts are preserved. Its pinned 1.2.54
[official implementation](https://github.com/kanboard/kanboard/blob/v1.2.54/app/Api/Procedure/MeProcedure.php)
returns a task list from `getMyDashboard`, unlike the older documentation's
combined object. The adapter uses fixed `getMyProjects` and `getMyDashboard`
reads separately. This compatibility correction requires fresh receipts for
all six adapters sharing that provider source.

The accepted lifecycle task scripts retain their exact original line endings
through explicit Git attributes. Three existing Windows probe files contain
CRLF bytes; silently normalizing them would invalidate the recorded probe hash
in a fresh checkout. This preserves the tested bytes rather than changing the
proof or repeating unchanged app workloads.

Remaining boundaries: native WebView flows, fresh Windows engine setup and
large workloads are separate gates. This does not verify all app functions or
make an unrestricted same-Windows-user agent a sandboxed process.
